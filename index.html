AI data analysis you can follow, from your data to every number.

Upload your data and ask a question in plain words. BambooAI does the analysis itself: it writes and runs Python one step at a time, reads each result before deciding what to do next, and reads any notes or documents you’ve added along the way.

You get a report that says what it found, how sure it is and what it couldn’t establish, with charts and a plain-language version. Every step stays visible, and the code map shows how each number was made, so you can check the work without reading the code.

See every step

As BambooAI works, each step appears in the app: the code it wrote, what that code printed, any attempt that failed, and the checks at the end. You can open any step to see exactly what it did.

Each analysis ends with a summary of its steps, time and cost. Every model call is logged with its prompt, tokens, time and cost, and you can open the exact prompt behind any step in the current thread.

The numbers and the words around them

Numbers tell you what happened. The notes people write around them often tell you why. BambooAI reads both, and every passage it reads keeps its place in the source, so you can check a quote against the original.

Hard data

Your measurements: power, heart rate, pace, load, sleep. Upload files (CSV, Parquet, JSON or .xlsx) or load them from Intervals.icu, Endura or SweatStack.

Soft data

Notes around the training
Load from Intervals.icu and BambooAI can bring in what was written around each session: the athlete’s comments, the coach’s replies, day notes, illness entries and the plan. Each keeps its date and author.
Your documents
Attach up to four papers, notes or interview transcripts to a thread. They’re split into numbered passages, and tables in them become data you can analyse.
The web
BambooAI can look up published figures during the analysis, with links to where they came from.

In one analysis

Your codebook
Each Intervals.icu note is read once, translated into English if needed, and tagged from a codebook you control, with codes like fatigue, recovery or deviation. If nothing fits, BambooAI suggests a new code and you decide whether to keep it.
Next to the numbers
The notes and their codes sit in the Python session as tables, so the analysis can line them up with your data. For example, the notes from the days around a drop in power.
Easy to check
A look-up brings passages back checked word for word against the source. The report cites them by place, like [C.417] for a note or [D1.17] for a document, next to the [cell 6] behind a number, and warns you when a citation doesn’t match anything. When it counts codes, it calls that the model’s reading of the notes.

Trace any number back to the data

When an analysis finishes, BambooAI reads its code and the session’s record and draws a map from your data to each number. The map is built by fixed rules, with no AI involved, so the same analysis always gives the same map, and it never shows anything the code didn’t do.

Worth checking

The map also points out what deserves a second look: inputs that were offered but never used, values typed straight into the code that results depend on, and results that came out empty or were replaced.

For example, the map might say:

CUT = 80000.0 is typed into cell 2, not read from the data; all 12 results rest on it

The map shows how a number was made, not whether it’s right. That call is still yours, and the reviewer’s.

You can open it from the summary at the end of an analysis, from a [cell n] citation in the report, or from the eye icon on any cell in the notebook.

What else it does

BambooAI started in sports science, where you measure the same people again and again and need to know where every number came from. It works on any tabular data.

Quick, Deep or Adaptive
Pick how much effort a question deserves: a quick lookup, a full analysis, or a longer investigation with a reviewer. Each mode has a budget of turns and cost, and the analyst knows it.
Follow-ups and branches
A follow-up carries on where the last run ended, with its variables still there. Branch off any earlier analysis, see them all on the thread map, or ask for five ideas on what to look at next.
A plain-language version
Every report also comes in plain English for readers who don’t code. You can save either one as a PDF.
Routines
Save a finished analysis as a routine and run it on new data without a model. Each run is checked and compared with the one before.
Memory
Save a run, and what BambooAI learned about the dataset, like column quirks and approaches that worked, is there next time.
Ask about a figure
Every figure has a chat button. Your question starts a follow-up run, with the picture included when the model is set up to read images.

Try it hosted, or run it yourself

It’s the same analyst either way. The difference is where it runs and which models it uses.

Hosted

Invitation beta

  • Nothing to install. It runs in your browser, on your own data.
  • Your code runs in a private sandbox, one per account.
  • Free to try on open models, with 20 queries a month. Stronger models and more computing power are pay as you go.
  • We’re letting people in gradually while we add capacity.

Open source

MIT licence, on GitHub and PyPI

  • The whole app runs on your computer. The code runs in a Docker container there, and your files stay with you.
  • Pick the model for each role: OpenRouter, OpenAI, Anthropic, Google, Groq, Mistral, xAI or DeepSeek, or your own models through Ollama or vLLM.
  • Prompts go to whichever providers you choose. Run every role on your own models and they stay on your network too.
$ pip install bambooai
$ bambooai serve

You’ll need Python 3.11 or newer and Docker. The README covers models, local hosting and everything else.
