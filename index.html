AI data analysis you can follow

Every analysis starts with an idea. Put it into words, then test it.

Upload your data and ask a question in plain words. BambooAI helps you set out what you think is going on, tests it step by step in Python, and then checks its own work. Every stage stays visible, so you can follow how the answer was reached.

1Analysis of the idea

Work out the question first

Before any analysis begins, the Architect works with you to find the right framing of the question, or the right representation of the problem. Without it, an AI model makes that choice on its own, usually without saying so.

  • What your view rests on

    The reasons you give are checked against the loaded data and marked holds, does not hold or cannot be checked.

  • Saved analyses

    Earlier work you saved on the same subject is found and shown as exact quotes, each with its date.

  • Figure drafts

    A draft of each figure appears in the brief before anything runs, drawn on made-up numbers when only your data can give the real ones.

2Analysis of the data

Work out the answer step by step

Each step of the analysis is visible as it happens, in full: the instructions the model received, its reasoning and working notes, the code it wrote, what that code printed and any attempt that failed.

  • Held to the brief

    What you expected and each other explanation are tested. If the data can’t give what the brief fixes, the analyst asks you instead of putting something else in its place.

  • Quick, Deep or Adaptive

    Pick how much effort a question deserves. Each mode has a budget of turns and cost, and the analyst knows it.

  • The context around the numbers

    It also reads the notes written alongside your data and the documents you attach, and cites each passage by its place in the source.

3Analysis of the work

Check the work

An AI model can write a long analysis in minutes, much faster than anyone can read it closely. So BambooAI keeps a full record of the work, and when the analysis ends, it checks the report against it.

  • The result and the brief

    The brief shows whether you saw what you expected, and what came of each other explanation.

  • Number checks

    Every number in the report is compared with what the code printed. One that doesn’t match is flagged, not silently corrected.

  • Replay

    The code behind the cited results runs again in a fresh Python session, and the numbers are compared with the first run.

  • The reach report

    It lists anything the code touched outside your data, and whether your question asked for it.

  • The reviewer

    In Adaptive mode, a second model with its own instructions reviews the evidence every eight turns.

  • Usage and logs

    Every model call is logged with its prompt, tokens, time and cost.

↻After the analysis

Next questions, memory and routines

  • Next questions

    When a run ends, BambooAI suggests where to go next, based on what the analysis found or left open. A follow-up carries on where the run ended, and the thread map shows every branch.

  • Memory

    The analyses you save become the Architect’s memory. Where they disagree, it says so and asks which way to go.

  • Routines

    Save a finished analysis as a routine and run it on new data without a model.

Framed, grounded and visible

Most of the work is in the question. It is framed with you, checked against the data and reframed, before the analysis and after it. The analysis is held to that frame and grounded in your data, and every step stays visible.

  • Built for scrutiny

    AI-generated analysis should be open to the same scrutiny as any other analytical work. Reproducible calculations are part of that, and so are the question, the choice of methods, the assumptions and the interpretation, which still need a person to think them through.

  • Inspired by the notebook

    Analysts have long shown their work in notebooks: the code, what it printed and the notes, in order, in one Python session that keeps what each step built. BambooAI keeps every analysis that way, and that is what you read, what the checks test and what the replay runs.

  • Open and configurable

    BambooAI is open source, under the MIT licence. Use it hosted, or run it yourself and choose the model for each role, from the main providers or your own through Ollama or vLLM. Every part can be changed, down to the instructions each model follows.

Try it hosted, or run it yourself

It’s the same BambooAI either way. The difference is where it runs and which models it uses.

Hosted

Invitation beta

  • Nothing to install. It runs in your browser, on your own data.
  • Your code runs in a private sandbox, one per account.
  • Free to try on open models, with 20 queries a month. Stronger models and more computing power are pay as you go.

Open source

MIT licence, on GitHub and PyPI

  • The whole app runs on your computer. The code runs in a Docker container there, and your files stay with you.
  • Pick the model for each role: OpenRouter, OpenAI, Anthropic, Google, Groq, Mistral, xAI or DeepSeek, or your own models through Ollama or vLLM.
  • Prompts go to whichever providers you choose. Run every role on your own models and they stay on your network too.
$ pip install bambooai
$ bambooai serve
